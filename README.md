# GAPGUARD 2.0

GCP와 오픈소스를 기반으로 확장 가능한 현장 데이터 수집·처리 구조를 검증하는 GAPGUARD 차기 프로젝트입니다.

GAPGUARD 2.0은 데이터스쿨 3차 프로젝트에서 구현한 기존 GAPGUARD를 출발점으로 삼습니다. 현재 2.0 코드는 아직 구현되지 않았으며, 기존 코드와 운영 경험을 검토한 뒤 필요한 부분을 이식·재구성합니다.

## 프로젝트 방향

- GCP 환경을 기준으로 설계
- 오픈소스 중심의 구성과 운영 자동화
- Terraform 기반 IaC
- CI/CD 파이프라인을 통한 반복 가능한 배포
- VM 기반 다수 현장·구역·디바이스 부하 재현
- 로드밸런서 등 부하분산 구조 검증
- GCP 총비용 `$300` 이내를 설계 제약으로 관리

## 목표 구조

```text
현장 디바이스/시뮬레이터
          |
          v
    VM 수집·처리 계층  <---- 부하 생성 및 확장 시나리오
          |
          v
   Load Balancer / 분산 계층
          |
          v
      오픈소스 저장·처리 계층

Terraform  ->  GCP 인프라
CI/CD      ->  테스트·빌드·배포
```

초기 검증에서는 전체 구조를 축소합니다. Azure Data Explorer(ADX), Azure Digital Twins(ADT), 복잡한 웹 애플리케이션 계층은 범위에서 제외하고, VM 확장·부하 생성·부하분산·배포 자동화에 집중합니다.

## 규모 가정

초기 부하 시나리오는 여러 현장과 구역, 디바이스를 모델링합니다. 예시로 약 8개 현장과 40개 구역을 고려할 수 있으나, 구체적인 현장·구역·디바이스 수는 부하 목표와 GCP 비용 검토 후 확정합니다.

## 범위 밖

- ADX 및 ADT 도입
- 복잡한 웹 프론트엔드와 관리 화면
- 규모 수치의 최종 확정
- 운영 환경으로의 무승인 배포

## 구현 순서

1. 기존 GAPGUARD 3차 프로젝트 코드와 실행 구조 분석
2. 최소 데이터 흐름과 부하 모델 정의
3. VM·네트워크·로드밸런서 Terraform 구성
4. 다수 현장·구역·디바이스 부하 생성
5. CI/CD에서 테스트·이미지 빌드·배포 자동화
6. 부하분산 효과, 장애 시 동작, 비용을 검증

## 저장소 원칙

- 비밀키, 서비스 계정 키, `.env`, Terraform state 파일은 커밋하지 않습니다.
- 인프라 변경은 Terraform 코드와 검증 결과를 함께 관리합니다.
- 현장·구역·디바이스 규모는 비용과 부하 결과를 근거로 갱신합니다.
